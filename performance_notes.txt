Performance notes :

Mesh composed of Cell structures which contain the informations about position and quantities inside the cell : 
for 10000 iterations (100s with 0.01s step) on a 100x1x40 mesh : 98009 ms (debug) - 4022 ms, 4019 ms, 4020 ms (release)

After optimization :
for 10000 iterations (100s with 0.01s step) on a 100x1x40 mesh : 67848 ms (debug) - 1730 ms, 1817 ms, 1767 ms (release)

Using RefCells :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 243 ms, 259 ms, 232 ms (release)

After cleanup :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 200 ms, 198 ms, 296 ms (release)

With 4 meshes :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 201 ms, 211 ms, 196 ms (release)

With new equation system :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 843 ms, 838 ms, 977 ms (release)

Optimizing new equation system ('Properties' to use references instead of clones) :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 298 ms, 317 ms, 306 ms (release)

Custom data structure defined by lib user :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 303 ms, 249 ms, 273 ms (release)

Update properties using the LHS equation :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 299 ms, 299 ms, 280 ms (release)

Equations process vectors<f64> instead of f64 :
for 10000 iterations (0.001s with 0.000001s step) on a 100x1x40 mesh : way too long (debug) - 817 ms, 868 ms, 830 ms (release)
the stop_criterial function accounts for approx 200ms, that should be reduced

Optimize meshing and other minor changes :
